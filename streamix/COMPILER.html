Streamix Compiler ​

Enable the React, Vue, or Angular compiler integration. Installing the runtime alone does not rewrite code.

Standalone command ​

sh
npm run sxc -- --check -p tsconfig.json # workspace
sxc --check -p tsconfig.json           # installed package; requires TypeScript
sxc --emit --outDir dist/app
sxc --explain --json
sxc --emit --watch                    # rebuild after edits
sxc --build tsconfig.json            # references, dependencies first
sxc --build --check                   # graph check; no files written
sxc --build --watch --json            # one JSON record per rebuild

Restart the TypeScript server, allow local plugin loading, and use the same TypeScript version as the build. Hovers, diagnostics, and safe fixes use the shared project pipeline. Emit with sxc --watch (or sxc --build --watch for references); the plugin does not compile on save. Project-wide errors use TypeScript's project diagnostics. Framework plugins are separate. Cross-file diagnostic locations and fixes follow unsaved snapshots. Referenced projects use editor snapshots to build declarations in memory; declaration-only keys remain conservative. An invalid dependency blocks dependent hovers and emission until fixed. Reference analysis runs synchronously and reuses unchanged projects.   compilerHost,
  referenceResolutionVersion: () => resolverRevision,

Values and sources ​

ts
import { atom, derived, flow, pipe, $ } from '@epikodelabs/streamix';

const count = atom(2);
type Source = typeof count;

const snapshot = count;               // alias keeps the atom
const doubled = derived(() => count * 2); // -> count.value * 2; stays reactive
const source = $(count);              // keeps the atom
send(count);                          // keeps the atom; no value requirement
send($(count));                       // sends the atom explicitly
count.next(3);                        // source methods stay unchanged
const explicit = count.value;         // no second .value
const example = derived(() => {
  const sources = [count];            // keeps the atom
  return inspect(count);              // unknown parameter: keeps the atom
});
const computed = derived(() => {
  target = count;                     // unknown target: keeps the atom
  return count;                       // formula result -> count.value
});
const tracked = pipe(count);
let mutable = pipe(count);
derived(() => { void tracked; void mutable; return 1; }); // both keep their sources; use void tracked.value to observe
const selected = derived(() => flag ? count : other); // reads the selected atom
const assigned = derived(() => target = count); // assigns the atom, returns its value
const view = derived(() => flag ? { count } : { count: other }); // fields keep sources
const local = derived(() => { const result = { count }; return result; }); // keeps source
const { item = count } = { item: void 0 }; // item is the atom
const doubledItem = derived(() => item * 2); // item.value * 2
const { snapshot: sampled }: { snapshot: number } = { snapshot: count }; // sampled is a number
const use: (arg: { n?: number }) => number = ({ n = count }) => n; // default reads value
const { item: mixed = 0 } = { item: maybe }; // may be a source or number
const choice = flag ? { item: count } : { item: 0 };
choice.item * 2;                       // Build error: item may be a source or value
const mixedSelection = flag ? count : 0;
mixedSelection * 2;                    // Build error: selected source or value
declare const index: number;
const items = [count, 0];
items[index] * 2;                     // Build error: dynamic selection is uncertain
const selectedItem = items[index];    // keeps the selected item
declare const dynamicKey: string;
const box = { item: count, [dynamicKey]: 0 };
box.item * 2;                          // Build error: key may replace the source
const holder = { item: count };
const wider: { item: Source | number } = holder;
wider.item = 7; holder.item * 2;        // Build error: item may no longer be a source
function replace(value: { item: Source | number }) { value.item = 7; }
replace(holder); holder.item * 2;      // Build error: helper can replace item
const list = [holder];
function replaceFirst(values: { item: Source | number }[]) { values[0].item = 7; }
replaceFirst(list); holder.item * 2;   // Build error: list[0] aliases holder
declare function opaque(value: { item: Source | number }): void;
opaque(holder); holder.item * 2;       // Build error: opaque call may replace item
// Imported helper bodies require a project Program; opaque calls remain conservative.
({ item: count, ...{ other: 1 } }).item * 2; // -> item.value * 2
const replacementKey: string = 'item';
({ item: count, ...{ [replacementKey]: 7 } }).item * 2; // no .value: the const key provably replaces item (TypeScript still rejects the static Atom type)
[count][0] * 2;                        // -> [count][0].value * 2
[count]['0'] * 2;                      // -> [count]['0'].value * 2
const sourceList = [count, 0];
sourceList[0] * 2;                     // -> sourceList[0].value * 2
const kept = sourceList[0];            // keeps count
[count][0]++;                          // publishes to count
[[count]][0][0]++;                     // nested fresh literals work too
([0, count] as const)[1] * 2;          // tuple type lets TypeScript check the selected item
const key = 'item' as const;
const { [key]: picked } = { ...options, [key]: count }; // picked is count
// An ES-module Program can also resolve imported constant keys.
const [first] = [count, ...others]; // first is count

Source identity is preserved unless the context explicitly requires a value. Explicit value contexts: arithmetic and comparisons (count * 2), typed value contracts (number parameters, annotations), destructuring or spreading a source, template spans, callee positions, payload member reads (profile.name), and direct formula results. Returned containers keep their sources; use .value for a snapshot. Source API members win over payload members: .value, .next, .subscribe and .pipe on a source are the atom API. A payload that declares next, subscribe or pipe is reached through the value read (profile.value.next) and warns (source-member-collision); profile.value itself stays the value read even when the payload declares a value member. Plain declarations alias the atom itself; containers, source-typed parameters, callbacks and every other untyped position keep the source. Imported contracts need a resolving TypeScript Program; array contracts also need lib types. Uncertain source-or-value reads are reported as uncertain-source-value by the shared file compiler, including in JavaScript without TypeScript checking. JSX children require renderable values; untyped component props keep their inputs:

tsx
<div>{items[index]}</div>             // Build error: source or value
<Component value={items[index]} />    // keeps the selected item
<Component source={count} values={[count]} /> // keeps sources
<div>{typeof count}</div>             // inspects the source

ts
declare function valueInput(value: number): void;
declare function sourceInput(value: Source): void;

valueInput(count);                    // -> valueInput(count.value)
sourceInput(count);                   // keeps the atom
const list = [count];                 // keeps the atom
const values: number[] = [count];     // -> [count.value]
const sources: Source[] = [count];     // keeps the atom
const fields = { count };            // keeps the atom
derived(() => ({ count }));           // keeps count
derived(() => ({ count: count.value })); // explicitly read a value
count === other;                      // -> count.value === other.value
Object.is($(count), $(other));         // compare source identity
typeof count;                         // inspects the source
!count;                               // -> !count.value
count instanceof Object;              // -> count.value instanceof Object
'value' in count;                     // -> 'value' in count.value
count && other;                       // both operands keep their sources
count || other;                       // both operands keep their sources
count ?? other;                       // both operands keep their sources
count ? 1 : 0;                        // -> count.value ? 1 : 0
profile?.name;                        // -> profile?.value.name (warns: name can mean payload data or source metadata)
profile['name'];                      // -> profile.value['name']

Custom helper contracts ​

ts
import type { SourceArgument, ValueArgument, FormulaArgument } from '@epikodelabs/streamix/compiler';

declare function fabric(input: SourceArgument<unknown>): void;
declare function render(input: ValueArgument<unknown>): void;
declare function compute(label: string, fn: FormulaArgument<() => number>): number;

fabric(count);                       // keeps the atom
fabric([count]);                     // keeps the array of atoms
render(count);                       // -> render(count.value)
render([count]);                     // array elements still stay atoms
compute('total', () => count);        // -> () => count.value
compute('total', async () => 1);      // Build error: synchronous formulas only
render.call(null, count);            // -> render.call(null, count.value): positionally static
fabric.call(null, count);            // keeps the atom
render['call'](null, count);         // -> render['call'](null, count.value)
render.apply(null, [count]);         // Build error: element contracts cannot be mapped statically
fabric.bind(null, count);            // Build error: bind defers arguments to a later call

Markers survive .d.ts emission. Conflicting contracts and atom-dependent generic inference produce build errors; use concrete value types or .value. The static call adapter keeps contracts by shifting them past the receiver; apply, bind, spread receivers, marked constructors, marked source/formula defaults, and value/formula spreads stay rejected with an explicit wrapper as the escape, because their argument mapping cannot be proven statically. See supported forms.

Assertions never request conversion ​

Ambiguous assertion contracts produce build errors. Use .value for snapshots. An annotation such as number[] requests values; satisfies number[] checks the existing sources and does not request conversion. These rules also apply to nested containers, aliases, spreads, and tuples.

ts
count satisfies Source;                         // OK: source
((count satisfies Source))!;                    // OK: wrappers preserve the source
count as number;                                // Build error
count as any;                                   // Build error: ambiguous
count satisfies (Source | number);              // Build error: ambiguous
count.value satisfies number;                   // OK: snapshot
(count + 1) satisfies number;                    // -> (count.value + 1) satisfies number

[count] satisfies Source[];                     // OK
[count] satisfies number[];                     // Build error
[count.value] satisfies number[];               // OK
([count] as const) satisfies number[];           // Build error
[count] satisfies [Source?];                    // OK: optional source slot
[1, ...sources, count] satisfies [number, ...Source[]]; // OK: source-only rest

({ count }) satisfies { count: Source };         // OK
({ count }) satisfies { count: number };         // Build error
({ count: count.value }) satisfies { count: number }; // OK

Object overrides must be proven ​

ts
declare const key: string;
declare const optional: { count?: number };

({ ...fields, count: count.value }) satisfies { count: number }; // OK: final snapshot
({ count: count.value, ...fields }) satisfies { count: number }; // Build error: final source
({ count, ...optional }) satisfies { count: number };           // Build error: source may remain
({ count, [key]: 0 }) satisfies { count: Source };               // Build error: key may overwrite count
({ count, [key]: count }) satisfies { [key: string]: Source };   // OK: every override is a source

declare const tag: unique symbol;
({ [tag]: count }) satisfies { [tag]: Source };                 // OK: symbol identity is preserved
({ get count() { return count; }, set count(value: Source) {} }) satisfies { count: number }; // Build error: setter keeps getter

Build errors and portable alternatives ​

ts
derived(async () => 1);              // Build error: formulas must be synchronous
const task = async () => 1;
derived(task);                       // Build error: named/aliased Promise return
derived(() => Promise.resolve(1));    // Build error, including imported PromiseLike signatures
flow(async () => 1);                 // Build error: flow expects an iterable
flow(async function* () { yield 1; }); // OK

const formula = () => count + 1;
derived(formula);                    // OK: implicit reads are lowered in place
derived(() => count + 1);            // OK: inline formula
const explicitFormula = () => count.value + 1;
derived(explicitFormula);            // OK: explicit reads

function transport() { return { count }; }
derived(transport);                  // Keeps count; no specialization needed
let mutable = () => count;
derived(mutable);                    // Build error: mutable callbacks cannot be specialized safely

let writable = atom(1);
const before = writable++;          // before = 1; publishes 2
const after = ++writable;            // after = 3; publishes 3
const assigned = writable += 2;     // assigned = 5; publishes 5
writable ||= fallback();            // RHS and publication only when falsy
count.next(count.value + 1);         // Explicit write also works with const bindings

Shared compilation API ​

ts
import { compileSource, compileProject } from '@epikodelabs/streamix/compiler';

const result = compileSource(sourceText, { fileName: 'app.ts', program });
if (!result.success) report(result.diagnostics); // original code; no edits

// Whole projects: imported types reflect lowered exports.
const project = compileProject(program, { host }); // supplied TypeScript CompilerHost
if (project.success) {
  const { outputFiles } = project.emit(); // JavaScript + declarations, in memory
}

Explain mode ​

compileSource(source, { explain: true }) adds result.explanations: one record per decision the compiler made, each with a source span, a decision kind (value-read, source-transport, write-lowered, formula-specialized, rejected, warning), a stable rule identifier, and a human-readable reason. The rule identifiers are the same constants the lowering engine emits (source-preserved, declaration-source, escape, source-selector, container-property, array-element-contract, callback-return, named-formula-specialized, …); EXPLANATION_RULES maps them to messages for hover tooling and documentation generators.

Changed ASTs are rebound to the current Program. Unknown dependencies invalidate conservatively. Project type checking and emission use a fresh Program; rebuild speed depends on the project. sxc --watch uses project sessions. Sessions retain up to three semantic versions per file within maxEntries. Project sessions store read, write, named-formula, and error plans without retaining their original ASTs. Plans containing foreign or synthetic nodes are not cached.

Guarantees and details ​

Identical source, checker, and options produce identical output. Lowering is source-preserving and idempotent; edit ranges are validated and result records are frozen. Introspection paths need a stable sourcePath or matching rootDir for reproducibility across checkouts. JSX and template behavior belongs to the framework integrations.

See the detailed reference for API contracts, limitations, host boundaries, introspection, and diagnostics.
