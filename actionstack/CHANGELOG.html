Changelog ​

5.0.3 - 2026-10-27 ​

  • Preserve results from injected nested thunk dispatches while keeping exclusive workflows locked until their awaited work finishes.
  • Deliver confirmed current selections to new subscribers even when values deduplicate, propagate pending readiness through module streams, and prevent delayed teardown from disposing a newer connection.
  • Unify module load and population rollback across configuration, registries, dependencies, and state installation; failed modules can be repaired and loaded again. Observer failures after commit are logged without undoing a successful installation.
  • Preserve inferred thunk result types for direct, nested, and module dispatches, and reject action-creator factory failures through the returned promise.
  • Finalize nested fresh objects, arrays, and collections without leaking draft proxies; reject accessor properties before executing them and preflight non-extensible write targets before committing any change.
  • Honor disabled system dispatches during initialization and lifecycle events, preserve the disabled markers, and keep literal dotted reducer keys distinct from nested paths.
  • Preserve nested dependency object and array structure without hoisting fields or creating self-references, and declare the Angular adapter's optional peer in the published library metadata.

5.0.2 - 2026-10-26 ​

  • Fixed module reloads being skipped when an unload was still queued, and duplicate registration from simultaneous loads. Await store.loadModule(module) before using module actions or selectors.
  • Unloading now destroys the module lifecycle and disposes its selector streams. After reloading, acquire fresh module.data$ streams; Angular components must notify change detection when assigning these streams asynchronously.
  • Rejected selector propagation completions now produce a console warning and allow later dispatches to continue when awaitStatePropagation is enabled.
  • Handler and reducer errors abort the action transactionally. A failing action handler or thunk rejects the dispatch promise after being logged — module action methods and store.dispatch now surface failures to their callers, and a thunk's return value becomes the dispatch resolution. Reducer failures stay contained with earlier stages retained, and automatically triggered thunk failures are logged without failing the triggering action.
  • Module action methods return the dispatch promise instead of the action object, making await module.actions.someAction(...) wait for processing to complete. A thunk's return value becomes the dispatch resolution, and its result type is inferred: ThunkCreator and BoundAction carry TResult, so awaited bound thunks are typed by what the thunk returns.
  • Dispatching on a destroyed or unconfigured module rejects the action's promise instead of throwing synchronously, and thunk failures are logged once by the starter (the thunk wrapper no longer double-logs), giving processing failures a single channel.
  • Halved tree-validation cost per action: state is no longer re-validated when a batch is created, and stages that change nothing skip the walk entirely. Collections with custom own properties are still rejected before a draft reads them.
  • Dispatches no longer walk untouched state: commits resolve recorded placements instead of scanning the tree, and finalize skips clean subtrees. No-op dispatches are O(1) regardless of state size; benchmark dispatches on 50k-object states dropped 20–60% (npm run benchmark:mutations).
  • Event-only actions (action('PING') without a handler) keep their module slice instead of replacing it with undefined.
  • The core entry point no longer imports Angular: atomToSignal moved to a separate @epikodelabs/actionstack/angular entry (optional @angular/core peer), so React or Node consumers can import the core package without Angular installed.
  • Pending selections always reach suppressed subscribers even when they resolve to the cached value (resolutions bypass dedupe while a stale replay was skipped), and module data$ no longer replays its stale cache while the upstream selection is resolving.
  • Module-load rollback is complete: registration, dependency injection, and state installation share one failure boundary, so any failure unwinds all of it.
  • BoundAction keeps creator metadata but no longer preserves the creator's action-returning call signature: bound methods are typed as promise-returning only.
  • data$ selector types unwrap async selectors (Awaited<ReturnType<...>>), matching the values atoms actually emit.
  • Path utilities treat only canonical numeric strings as array indices ("01" stays a property name), and combineReducers lets child reducers initialize missing intermediate branches instead of throwing during traversal.
  • dispatchSystemActions: false is now honored, and exclusive-mode error logging handles non-Error throws without losing the message.

5.0.1 - 2026-10-26 ​

Rebuilt how handlers update state and how selectors observe it: mutation drafts, transactional in-place commits, and read-tracked selectors. Upgrading from 4.x requires no changes to user code — the public API is unchanged, and handlers that return replacement state keep working exactly as before.

  • Action handlers and global reducers now receive a temporary proxy draft. Mutate the draft and return nothing (or return the draft itself), or return replacement state as before — mixing both in one handler throws. Drafts are revoked when the handler settles, so they cannot be retained.
  • Handler writes are journaled privately and committed once per action after all handlers and global reducers succeed. A failing global reducer loses only its own writes while earlier successful stages of the same action are retained.
  • Commits update existing objects and arrays in place instead of producing new references. Retained state references therefore observe later commits, and storeFreeze is no longer combinable with mutable handlers.
  • Store-backed selectors (store.select, module data$) now track the state paths they read and rerun only when a committed change overlaps those paths. Whole-object selections emit after nested changes even when the reference is unchanged; primitive results still suppress equal values. Any change beneath an array — length, an index, or iteration — invalidates selectors reading that array.
  • Async selectors read live state and can observe commits that land after an await. A commit during a pending evaluation discards its result and coalesces into a fresh evaluation when it settles.
  • With awaitStatePropagation: true, dispatch now also waits for selector evaluations and delivery to their sources before the browser idle boundary.
  • createCurrentSource accepts a custom equals policy; store-backed streams use it to re-emit objects updated in place while still deduping equal primitives.
  • State must be a tree of plain objects, arrays, Map, Set, and Date values with data properties. Cycles, shared mutable references, and accessors are rejected.
  • Map, Set, and Date values are no longer fully opaque: handlers mutate them through their methods (map.set, set.add, date.setMonth) and selectors read them through theirs (map.get, set.has, date.getTime). Method calls are journaled privately and replayed onto the original instance at commit; Map values and Set members are wrapped too, so nested writes stay inside the transaction. Any change to a collection invalidates selectors reading it as a whole. Class instances and accessor-based values remain replace-only because their methods cannot be reliably intercepted.

4.0.6 - 2026-10-25 ​

  • Aligned Streamix and Actionstack dependencies, bumping Streamix to 3.0.10 and updating Actionstack's peer dependency requirement to >=3.0.10.

4.0.5 - 2026-10-25 ​

  • Updated development dependencies to Streamix 3.0.9 and adjusted the published peer range to support Streamix 3.0.6 or 3.0.9 and later.
  • Retained Angular 21 and TypeScript 5.9 with project-local legacy peer resolution for consistent npm install and npm ci behavior. Refreshed installed dependencies and regenerated the dependency lockfile.

4.0.3 ​

Updated compatibility with @epikodelabs/streamix 3.0.3. Fixed selector, store, and module data streams to account for Streamix atoms replaying their current value on subscription, eliminating duplicate initial emissions and stale values after resubscription. Current-value sources now reconnect and refresh correctly while preserving derived, nested, and asynchronous selector updates.

4.0.2 ​

Fixed selector stream lifecycle semantics after the Streamix v3 migration. store.select(), module data$ selectors, selectStream(), and selectStreamAsync() now preserve their current value across unsubscribe/resubscribe cycles, immediately deliver the latest selected value to new subscribers, and remain reusable after their subscriber count drops to zero. Module selector streams now dispose correctly when their module is unloaded, while attached view notifications stay aligned with actual selector emissions. Replaced the redundant createSharedSource wrapping with a shared current-value source primitive and added regression coverage for selector resubscription and lifecycle behavior.

4.0.1 ​

Migrated Actionstack to Streamix 3.0.1. Store selectors and module data$ accessors now return atoms, loaded$ and destroyed$ are writable atoms, and subscriptions are callable teardown functions rather than objects with .unsubscribe(). Removed the old query()/observer-object stream assumptions from the library, tests, and demo apps, replaced isStream with isAtom, updated docs for pipe(...) composition, and aligned the Angular and React examples with manual atom subscriptions.

3.0.25 ​

Made module.data$ selector factories available immediately at createModule(...) time, while keeping the underlying selector streams deferred until the module is configured and loaded. This fixes early field-initializer usage such as module.data$.selectTopHeroes() before store.loadModule(module), updates module load ordering so selector streams attach only after state is published, aligns custom streams with the Streamix 2.0.53 Stream contract by adding toArray(), and moves jasmine/node typings into the spec tsconfig so library builds no longer require test-only type definitions.

3.0.24 ​

Simplified module selectors to plain state-accepting functions and removed selector factory support. Fixed batched module population so modules are configured before registration, ensured nested dispatches from directly dispatched thunks still flow through starter trigger handling, and clarified duplicate registration warnings to reflect that existing handlers and thunks are preserved. Also made the hash spec Node-safe and added package-local TypeScript configs so library tests resolve jasmine and node globals correctly in editors.

3.0.23 ​

Replaced the tracker-based awaitStatePropagation mechanism with a lightweight waitForBrowserIdle() helper that uses requestIdleCallback, requestAnimationFrame, or setTimeout as fallback. Simplified the select subscription flow by removing tracker integration, using a stopped flag instead of subscription.unsubscribed, and extracting a resolveSelected helper for cleaner error handling. Added jasmine and jasmine:coverage npm scripts for headless browser testing. Removed the withTracker enhancer usage from the demo app and eliminated the tracker property from the Store type.

3.0.20 ​

Verified full API compatibility with @epikodelabs/streamix 2.0.38.

3.0.17 ​

Improved concurrent starter resilience when next() throws (logs and clears inflight), expanded starter stress coverage, and refreshed npm-visible package description.

3.0.16 ​

Removed the tracker/trackable utilities and the 'awaitStatePropagation' option so state propagation no longer waits for tracked streams.

3.0.15 ​

Modules are now managed entirely through the new helpers: registerModule(store, module) and unregisterModule(store, clearState, module). We have finally removed the old init(store) and destroy(clearState) methods from modules (yeah, those were kinda creepy 😅).

3.0.14 ​

Callable thunks also respect selected strategy (not just plain actions anymore), added robust thunk triggering based on action type or predicate functions, optimized lock usage to minimize held time while preserving serialized state access, improved error handling with descriptive messages, and enhanced concurrent scheduling of thunks for better performance and reliability.

3.0.10 ​

Removed ExecutionStack, due to previously eliminated epics and sagas middlewares. Continued emphasis on using only thunks and callable thunks for handling asynchronous logic and side effects, enhancing simplicity and predictability. Small fixes in module implementation.

3.0.9 ​

Introduced trackable(), a stream decorator which adds trackability to applied stream. Made the tracker property publicly accessible on the Store type, enabling usage of trackable() and other tracker utilities outside the store context

3.0.8 ​

Actionstack V3 replaces epics and sagas with callable thunks — simpler async handlers triggered directly or by actions. This reduces middleware complexity and boilerplate while improving type safety and modular side-effect management.

3.0.7 ​

Removed MainModule type — no longer required by createStore. Added addReducer method to support dynamic reducer registration. module.init(store) and store.loadModule(module) are equivalents. Replaced middlewareAPI property with a getter to defer access and ensure correct store context.

3.0.6 ​

Introduced populate() method to initialize and register multiple static modules at once. Useful for bootstrapping app-level modules in a single call. Corrected code samples in README.md

3.0.5 ​

The documentation has been expanded with practical examples and usage samples to help developers get started quickly and understand the core concepts more clearly. This release also updates dependencies and changes the compilation target to ES2022 for improved modern JavaScript support.

3.0.4 ​

Modules can be registered under nested paths using slice: 'foo/bar'. Actions will apply updates to nested state objects based on their full slice path (e.g., foo/bar/MY_ACTION targets state.foo.bar). All internal state management functions (getState, setProperty, dispatch, loadModule, etc.) now support both string and array paths transparently. Utility function normalizePath(path: string | string[]): string[] added to unify path handling.

3.0.1 ​

Redesigned core architecture to eliminate traditional reducer logic. Introduced fully modular "slices" using colocated state + actions (inspired by Zustand, but type-safe). Actions are now defined using the new action() utility that bundles. No more reducers in the usual sense — state updates are handled via registered action handlers. Type inference has been improved across actions, selectors, and middleware.

2.2.3 ​

Improved typings for createAction to reflect the overloaded behavior, enabling stronger type safety and better autocompletion in editors.

2.2.1 ​

Corrected the initialization logic of the store enhancer to ensure it receives the fully constructed store instance instead of new store creator. This ensures the enhancer accesses the store only after it’s fully initialized, preventing issues with repetitive or premature store initialization and supporting more predictable enhancer behavior.

2.2.0 ​

Support for Streamix v2.0.1. Actionstack now fully integrates with the updated async iterator–based operators introduced in Streamix 2.0.1, improving compatibility, performance, and debugging clarity.

2.1.5 ​

Fixed an issue where the store was being initialized twice and middlewares were receiving a stale dispatch due to premature destructuring of middlewareAPI; corrected the logic to initialize the store only once and ensure that all middlewares receive the final composed dispatch via a shared, lazily-evaluated reference.

2.1.1 ​

In version 2.1.1, several improvements were made to enhance functionality and reliability. The getProperty and setProperty methods in the utils module were added, providing better support for accessing and modifying object properties consistently across different environments. Additionally, updates were made to the configuration files, improving compatibility with various setups and ensuring smoother operation.

2.1.0 ​

The new version includes several important improvements and fixes, including updated support for epics operators, changes to selectors and methods like update, as well as adjustments to the project structure with streamix.

2.0.9 ​

In version 2.0.9 of Actionstack, we've integrated the streamix project into our codebase, enhancing our state management capabilities with asynchronous actions and reducers. We also updated our documentation to reflect these changes and added a test app for streamix usage.

2.0.8 ​

This release introduces several key improvements, including a restructured package organization and enhanced documentation for better integration with Angular applications. The mainModule has been refactored to use helper modules like combineReducers, combineEnhancers, and createStore, improving modularity and maintainability. New features include the addition of type safety through collision-resistant reexporting and improved error handling in sagas. Additionally, there are updates to store initialization logic to make it more robust and compatible with Redux middlewares.

2.0.0 ​

The Actionstack v2.0.0 release introduces several significant improvements and new features, enhancing both functionality and maintainability. Key updates include renamed 'lock' to 'simpleLock' to prevent name collisions, added jsdocs for store methods, and corrections in package imports. The documentation was also updated to reflect these changes, ensuring users have access to the latest information. Additionally, functional tests were implemented for actionHandler, tracker, executionStack, and other core components, improving test coverage and reliability. Dependencies were streamlined by removing those from Angular, contributing to a cleaner and more efficient dependency management system.
